## 一、项目背景与目标

### 1.1 背景

内容团队（个人/小团队）日常需要研究爆款短视频（抖音 / B站 / YouTube / 快手 / 小红书等），传统做法是人工观看 + 手工记录，效率低且难以沉淀。行业已有"数据平台（选样）→ 工具提取（转写/抽帧）→ AI 结构化解析 → 人工校准 → 公式入库"的成熟方法论（见调研报告），但市面工具存在明显空白：

| 竞品类别 | 盲区 |
|---|---|
| 平台官方工具（热点宝/巨量算数） | 只给"哪些视频火"，不给"为什么火" |
| 数据平台 SaaS（蝉妈妈/飞瓜） | 贵、面向团队、AI 深拆刚起步且浅 |
| AI 拆解工具（VideoLens 等） | 面向 AI 视频创作者（反推提示词），不做运营视角拆解，结果不留存 |
| 通用 AI 笔记（NotebookLM 等） | 通用总结视角，不对齐运营拆解维度，无格式沉淀 |

**空白点**：没有一款工具解决"把爆款拆成**我的钩子库/脚本库/公式资产**"这件事。

### 1.2 产品定位

**拆片**：个人自用的本地短视频逆向解析工作台。输入视频链接（或本地文件），自动完成"下载 → 转写 → AI 七维拆解（+画面提示词反推）→ Markdown 报告 → 本地库沉淀"，把"感觉上好看"变成"可复制、可验证、可培训"的公式。

- **做**：链接/文件 → 七维拆解报告 → 本地库（钩子库/提示词库）→ 检索与复用 → 提示词改写（可灵/即梦/Seedance 可直接粘贴）→ 单图六维反推（封面/截图速拆）
- **不做**：榜单采集（用热点宝/蝉妈妈免费版选样）、团队协作、全网素材库、内容发布
- **核心资产**：七维拆解 prompt 模板 + 钩子类型/结构骨架清单（差异化所在）

### 1.3 一句话描述

> 粘贴链接 → 下载 → 语音转写 → AI 七维拆解（+画面提示词反推）→ Markdown 报告 + 本地库。把爆款视频拆成可复制的公式。

## 二、用户与使用场景

### 2.1 目标用户

| 用户 | 典型诉求 |
|---|---|
| 个人创作者 | 研究对标账号，找选题、钩子、结构可复用的方法 |
| 内容运营/编导 | 每天精拆 1 条 + 快拆 5 条，沉淀团队公式库 |
| AI 视频创作者 | 反推爆款画面，拿到可直接粘贴的文生视频/图生视频提示词 |

### 2.2 核心使用场景

1. **深拆一条爆款**（SOP 精拆）：粘贴链接 → 等待 5~15 分钟 → 拿到 12 节完整报告 + 自动入库；
2. **快拆**：只看报告前 3 秒钩子、结构骨架、公式提炼部分；
3. **公式复用**：写新脚本前检索钩子库（"悬念提问 + 利益承诺"类公式）、按可迁移选题取用；
4. **AI 视频复刻**：启用画面提示词反推 → 提示词库 → 一键改写为可灵/即梦/Seedance 格式 → 复制粘贴；
5. **本地素材直拆**：已下载到本地的视频/音频文件直接上传或 CLI 传路径，跳过下载环节；
6. **封面速拆**：看到爆款封面/精彩单镜头，上传图片 30 秒内拿到六维分析 + 可直接粘贴的 AI 生成提示词；
7. **无网/低成本场景**：本地 faster-whisper 转写免费、离线可用。

### 2.3 使用频次与量级

- 个人：每日 1~5 条，单条视频 ≤ 30 分钟（短视频为主），偶有 1~3 小时长视频；
- 库规模：一年累计几百条拆解记录（hooks.jsonl / prompts.jsonl 各数百条、index.csv 数百行、报告数百份）——**当前 JSONL/CSV 文件方案在此量级足够，无需数据库**。

## 三、现状系统概述（原理摘要）

> 详细原理与模块设计见《开发解决方案》。此处仅给出需求视角的系统全貌。

```
[输入] 视频链接 / 本地文件
   │
   ▼
① 下载解析（yt-dlp）：音频轨（必）+ 画面轨（vision 开启时）
   │
   ▼
② 语音转写：本地 faster-whisper（免费/离线）或 OpenAI 兼容 ASR API
   │
   ▼
③ AI 七维拆解：OpenAI 兼容 LLM（DeepSeek/豆包/智谱/OpenAI），强约束 JSON 输出
   │
   ▼
③.5 画面提示词反推（可选）：PyAV 抽帧 + 多模态视觉模型，分片分帧 → 文本 LLM 合并
   │
   ▼
④ 产出：Markdown 报告（12 节）+ 本地库（index.csv / hooks.jsonl / prompts.jsonl）
   │
   ▼
⑤ 复用：CLI/Web 检索钩子库、提示词库；一键改写为可灵/即梦/Seedance 提示词包
```

- **双入口**：`main.py`（CLI）与 `webui.py`（本地 Web，http://127.0.0.1:8765），共用同一套 `breakdown/service.py` 流水线；
- **零框架依赖**：Web 服务用 Python 标准库 `http.server`，前端纯原生 JS/CSS，无构建步骤；
- **依赖隔离**：第三方依赖（yt-dlp / faster-whisper / openai）安装到项目内 `vendor/`，不污染全局 Python 环境；
- **数据全部本地**：报告、库、临时媒体均在项目目录下，仅绑定 127.0.0.1。

## 五、功能需求详述

> 每条含：需求描述、规则/边界、验收标准。

### FR-01 视频链接输入与平台识别 【P0｜已实现】

**描述**：用户粘贴视频链接，系统识别平台并规范化为可解析的直链。

规则：
1. 支持站点：B站 / YouTube（含 youtu.be） / 抖音（含 iesdouyin、精选页 modal_id）/ 快手 / 小红书（含 xhslink 短链）/ 视频号 / 其他 yt-dlp 可解析站点；
2. 抖音精选页/搜索页 URL 自动规范化为 `https://www.douyin.com/video/<modal_id>`；
3. 平台识别用于 meta 记录与报告展示，不限制下载能力（下载能力取决于 yt-dlp 提取器）。

验收标准：
- [x] 粘贴 `https://www.douyin.com/jingxuan/xxx?modal_id=123` 能正确下载 id=123 的视频；
- [x] 报告/库中 platform 字段正确（B站/YouTube/抖音/快手/小红书/视频号/其他/本地文件）。

### FR-02 媒体下载（音轨/画面轨、cookies、重试） 【P0｜已实现】

**描述**：通过 yt-dlp 下载媒体。默认只下音频轨（转写用）；启用画面提示词反推时同时下载画面轨（抽帧用），音视频分轨、单流文件，**无需 ffmpeg 合并**。

规则：
1. 音频轨格式 `bestaudio/best`，视频轨 `bestvideo/best`；
2. 视频轨下载失败**降级**为纯音频，仅跳过画面反推，不影响主流水线；
3. 登录态支持两种：`--cookies-from-browser chrome/edge/firefox`（新版 Chrome/Edge 可能解密失败）与 Netscape 格式 `cookies.txt` 文件（推荐，Web 页面可持久化路径）；
4. 抖音等平台反爬为**概率性拦截**，下载失败自动重试 3 次、间隔 5 秒；
5. 下载失败时给出可操作的提示（cookies 导出方法指引）；
6. 元信息采集：标题、作者、时长、发布日期、播放/点赞/评论数、简介（截 500 字）、封面 URL。

验收标准：
- [x] B站 / YouTube 链接一次下载成功；
- [x] 抖音链接在提供 cookies 文件后可下载；
- [x] 视频轨失败时流水线继续完成（报告标注未做画面反推）；
- [x] 报告的 0.基本信息/1.数据快照节展示采集到的元信息。

### FR-03 本地视频/音频文件直拆 【P0｜已实现】

**描述**：支持上传本地媒体文件（Web）或 CLI 直接传文件路径，跳过下载步骤，自动探测时长后进入转写/抽帧。

规则：
1. 允许的扩展名：视频 mp4/mov/mkv/webm/avi/flv/ts/m4v/mts/m2ts/wmv/mpg/mpeg/3gp；音频 mp3/m4a/wav/aac/ogg/flac/opus/wma；
2. Web 上传：文件名需合法（不含路径分隔符、不以 `.` 开头），按 Content-Length 流式写入 `work/uploads/`（先写 `.part` 再原子改名），不落内存；
3. 时长探测用 PyAV（容器 duration → 流时长 → 帧数/帧率 逐级回退），探测失败记为 0 不影响流程；
4. meta.platform = "本地文件"，url = 文件名。

验收标准：
- [x] Web 上传 mp4 文件后走"上传→转写→拆解→报告"全流程；
- [x] `python main.py "D:\videos\sample.mp4"` 直接拆解；
- [x] 非法文件名/不支持的类型返回 400 并给出中文提示。

### FR-04 语音转写（双引擎） 【P0｜已实现】

**描述**：将音轨转写为带时间戳的分段逐字稿。引擎二选一：
- **local**：faster-whisper 本地推理（免费、离线可用、隐私好），CPU + int8 量化，模型缓存到项目内 `work/models/`（不依赖系统缓存目录）；
- **api**：任意 OpenAI 兼容 ASR 接口（如 OpenAI whisper-1），配置 `transcribe.openai_base_url / openai_api_key / openai_audio_model`，也可用环境变量 `ASR_API_KEY`。

规则：
1. 模型可选 tiny/base/small/medium/large-v3，默认取 `config.json` 的 `transcribe.whisper_model`（当前默认 medium），CLI `--whisper-model` / Web 高级选项可临时覆盖；
2. 转写语言默认 zh，可用 `--lang` 指定；
3. 本地转写参数：`vad_filter=True`（VAD 过滤静音）、`beam_size=5`；
4. **音轨预检**：媒体无音轨时提前给出可读错误（"该媒体文件没有音轨"），避免 faster-whisper/PyAV 晦涩的 IndexError；
5. 输出：`[{start, end, text}]`，渲染为 `[MM:SS-MM:SS] 文本` 行；
6. 缺失依赖时给出明确安装指引（`pip install --target vendor faster-whisper`）或建议切换 api 引擎。

验收标准：
- [x] 本地引擎完成中文口播视频转写，逐字稿带时间戳；
- [x] api 引擎配置后可转写并返回分段结果；
- [x] 静音视频报"没有音轨"可读错误，不抛 IndexError。

### FR-05 AI 七维拆解 【P0｜已实现】

**描述**：将"视频元信息 + 带时间戳逐字稿"交给任意 OpenAI 兼容 LLM，按七维拆解模型输出**严格结构化 JSON**。

七维：① 选题与定位 ② 标题/封面/话题 ③ 前 3 秒钩子 ④ 结构与脚本 ⑤ 画面与剪辑 ⑥ 声音设计 ⑦ 数据与评论区。

规则：
1. 输入模型（LLM 配置）：`llm.base_url / api_key / model`，支持 DeepSeek / 火山方舟豆包 / 智谱 / OpenAI 等，或环境变量 `LLM_API_KEY / LLM_BASE_URL / LLM_MODEL`；
2. 输出约束：`response_format={"type": "json_object"}` + 提示词内嵌完整 JSON Schema 示例（SCHEMA_DEMO）+ 枚举清单（钩子 8 类、骨架 5 套）；
3. **禁止编造**：逐字稿/元信息中没有的字段（完播率、评论区、封面细节、BGM）一律填空/null，报告标"待人工补充"；
4. 容错：LLM 调用失败重试 1 次；输出非合法 JSON 时追加提示重试 1 次；JSON 解析支持剥代码块、正则提取 `{...}` 兜底；
5. 温度 0.3，超时 600s；
6. `--json` 可额外输出 LLM 原始 JSON（调试 prompt 用）。

验收标准：
- [x] 输出可被 `json.loads` 解析，字段符合 SCHEMA_DEMO；
- [x] 未配置 LLM Key 时给出配置指引并以非零码退出（CLI）或任务失败（Web）；
- [x] 同一输入两次拆解结果结构一致（温度 0.3 保证稳定）。

### FR-06 画面提示词反推 【P1｜已实现】

**描述**（可选功能）：用支持图像的多模态模型反推"这条视频用 AI 怎么生成"的提示词——快速提示词（一行版，中英）、整体文生视频提示词（中英）、分镜级提示词表（含扩写完整版）、负面提示词、风格关键词、图生视频模板、复刻建议。

规则：
1. 启用条件：`config.json` 的 `vision.model` 非空（DeepSeek 纯文本模型不支持，需 gpt-4o / doubao-vision / glm-4.6v 等视觉模型）；
2. `vision.base_url/api_key` 留空则复用 `llm` 的；
3. **分片分帧策略**：按 `slice_seconds`（默认 40s）切片、每片 ≤ `frames_per_slice`（默认 8）帧、最多 `max_slices`（默认 8）片；短片一次调用，长片逐片调用后由文本 LLM 合并（时间排序、去重、重编号、汇总），合并失败降级为直接拼接；
4. 抽帧：PyAV 解码，片内均匀抽帧（约每 3 秒 1 帧、最少 4 帧、上限 max_frames），640×640 JPEG（质量 80）base64 内联传输，**无需 ffmpeg 二进制**；
5. **时间偏移自适应**：片内相对时间 +offset 转全局绝对时间；若模型直接输出绝对时间（超过片长 +5s）则不再偏移；
6. **覆盖度自检**：单次调用结果仅覆盖 <60% 时长时，自动对后半段补帧再反推并合并；
7. **快速提示词 + 负面提示词**：分镜输出必须附带一行 ≤60 字可直接粘贴的快速提示词（中英各一行）与负面提示词（逗号分隔的 AI 常见缺陷清单，如肢体形变/面部扭曲/闪烁/文字乱码）；分片合并时跨片去重合并（MERGE_SYSTEM 契约字段）；
8. **分镜级扩写**：合并完成后用文本 LLM（EXPAND_SYSTEM）把每个分镜的简短提示词扩写为 150~220 字可直接粘贴的完整提示词（主体+动作+环境+景别+运镜+光影色调+风格质感+画质），按时间字段回填（要求 ≥80% 分镜成功，否则保留原文，不阻断流程）；
9. **镜头语言术语约束**：景别用 ELS/LS/FS/MS/MCU/CU/ECU 标准术语，运镜用 推/拉/摇/移/跟/环绕/手持/滑动变焦 并加速度，角度尽量数值化（如 45°仰拍）；每镜须写出相对前一帧的变化；输出纪律：JSON 外不允许任何字符，禁止开场白；
10. 失败降级：单片失败跳过该片；扩写失败保留原文；全部失败不影响主报告（提示词反推失败只是警告）；`--no-vision` / Web 取消勾选可关闭；
11. 多模型预设：`vision.presets` 可配多套视觉模型，`vision.active` 切换生效，Web 高级选项下拉即时切换（写回 config.json），下次拆解生效；
12. 反推结果存入 `library/prompts.jsonl`（含 quick_zh/quick_en/negative_prompt 字段），可检索。

验收标准：
- [x] 3 分钟视频反推出 40+ 分镜提示词（分片合并生效）；
- [x] 单次调用只覆盖开头时触发补帧，最终覆盖全片；
- [x] 输出含 quick_prompt（中英）与 negative_prompt 字段，报告第 12 节 / 库记录 / CLI prompts 均可展示；

### FR-10 提示词改写 【P1｜已实现】

**描述**：把反推得到的原始提示词改写成**按模型分段、可直接粘贴到生成工具**的复刻提示词包。v3 起为"分段式"结构：把 3 秒级分析分镜合并成 5~8 秒的生成段（3~5 段），每段分别按 Seedance 2.0/2.5（五维架构：主体/动作/环境/镜头语言/光影氛围）、可灵、即梦三种格式改写，并带负向提示词与参数建议。

规则：
1. 入口：Web 提示词库记录上的"改写为可直接用的提示词包"按钮（消耗一次 LLM 调用），或 `scripts/demo_prompt_rewrite.py`；
2. 输入：整体提示词（中英）、快速提示词、原始负面提示词（改写时以它为主并补充完善，不丢弃）、图生视频模板、**分镜提示词列表**（scene_prompts，逐镜喂给模型）；
3. **分段规则**：按画面内容/场景切换/语义完整性把分镜合并为 5~8 秒生成段（不得少于 4 秒、不得多于 12 秒），时间字段首尾相连覆盖全片（上一段结束秒 = 下一段开始秒，首段从 0 开始，末段覆盖到视频最后），输入分镜的每个画面要点都必须归入某段、不得遗漏；
4. **全片一致性锚点**：所有段的 主体/场景/光线/色调/风格 描述词逐字复用；非首段提示词开头写"延续上一段：同一【主体】、同一【场景】，从上一段结尾画面继续"衔接句并点出段末停驻状态；**首段严禁出现任何衔接字样**（直接描述起始画面）；
5. **硬校验与自动重试**：输出后做时间轴校验（连续性/无重叠/段长 4~12 秒/覆盖原分镜时间轴 ≥95%/首段 0 秒/末段到结尾）+ 首段衔接校验，未通过则把错误反馈给模型重试 1 次；两次均未通过时仍返回结果并附 `warnings` 字段，前端警示展示；
6. **规范化**：segments 只保留 {time, summary, seedance_zh, kling_zh, jimeng_zh} 有效字段；无分镜输入时输出单个覆盖全片的分段；
7. 改写以原始反推画面细节为准，**禁止添加原画面没有的元素**；
8. 结果按 url 存入 `prompt_packs.jsonl`（同 url 覆盖），再次点击为"重新改写"；旧版本生成的包（无 segments）前端提示"重新改写提示词包"升级。

验收标准：
- [x] 改写结果含 segments[{time, summary, seedance_zh, kling_zh, jimeng_zh}]/negative/params 字段，时间轴连续覆盖全片；
- [x] 前端按模型分组（Seedance 在前）逐段展示，每段一键复制；时间轴状态行 + 复刻衔接建议（图生视频链条：上一段末帧作为下一段首帧）；
- [x] 校验失败自动带反馈重试，仍失败则展示 warnings；
- [x] 记录删除不影响已生成的 pack；旧格式 pack 可一键"重新改写"升级。

## 七、非功能需求

### 7.1 性能
| 项 | 指标 |
|---|---|
| 短视频（≤3 分钟）全流程 | 本地转写 + 文本拆解 ≤ 10 分钟；加视觉反推 ≤ 15 分钟 |
| 转写速度 | faster-whisper medium int8 CPU 约 1~3 倍速（随硬件浮动） |
| Web 响应 | 静态页/API 即时；日志轮询 1.5s 增量，无全量刷新 |
| 任务并发 | 当前不限（本地单机场景可接受）；规划上限 2（FR-18） |

### 7.2 可靠性
- 下载失败自动重试 3 次（FR-02）；视频轨失败降级（FR-02）；
- 视觉反推失败不阻断主流程（FR-06）；
- LLM 调用/JSON 解析失败重试各 1 次（FR-05）；
- 合并失败降级为拼接（FR-06）；
- config 读写原子化、防并发半截文件（FR-12）；
- JSONL 坏行跳过（FR-08）。

### 7.3 安全与隐私
- **仅绑定 127.0.0.1**，不暴露公网；
- API Key 明文存于 config.json（.gitignore 排除）；**建议**后续支持环境变量优先（已支持）与系统密钥链（规划）；
- 上传文件名消毒（拒绝路径分隔符/点开头）、扩展名白名单；
- Markdown→HTML 先 `html.escape` 再加工，防 XSS；`<script>` 不产生（selftest 已覆盖）；
- 任务日志不落盘（仅内存），重启即失（FR-18 规划持久化）；
- 仅学习研究自用，遵守平台协议与版权法规（README/页面页脚均有声明）。

### 7.4 兼容性
- Python 3.10+（当前以 3.13 验证），Windows 优先（也兼容 macOS/Linux）；
- 依赖安装到 `vendor/`，无全局污染；缺失依赖时给明确指引；当前依赖：yt-dlp / openai / faster-whisper / **Pillow**（单图反推图像预处理）；
- 模型/LLM 供应商可替换：任意 OpenAI 兼容接口（文本/ASR/视觉三通道独立配置）。

### 7.5 成本（用户视角）
- 本地转写免费；LLM 文本拆解单条约几分钱（DeepSeek 等）；
- 视觉反推按帧/片计费，`max_slices` 上限防止超长视频费用失控；
- Whisper 模型一次性下载：small ≈460MB / medium ≈1.5GB / large-v3 ≈3GB。

### 7.6 可维护性
- 模块单职责、CLI/Web 共用 service（单一数据流）；
- prompt 模板集中在 `prompt.py`（含七维/视觉/合并/扩写/单图六维五套模板，后续外置 FR-16）；
- `scripts/` 提供冒烟/端到端测试（selftest.py、test_pipeline.py、test_single_image.py 等），测试用临时目录不碰真实数据。

## 八、约束与假设

1. **平台接口易变**：抖音/小红书等接口频繁变化，下载可能随时失败——假设有 cookies 与重试机制可缓解，失败时可降级为本地文件直拆；
2. **模型能力差异**：视觉反推质量依赖所选多模态模型（glm-4.6v 旗舰需余额）；DeepSeek 纯文本不支持视觉；
3. **数据缺口是特性**：完播率、转发/收藏、评论区等后台数据**不可能**从下载接口拿到，报告以"待人工补充"标注——这是有意的设计（禁止编造），不是缺陷；
4. **单机单用户**：不做多用户/鉴权/服务化部署；
5. **本地量级**：库规模数百~数千条，无需数据库（FR-19 导出需求出现后再评估）。
