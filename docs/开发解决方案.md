# 第一部分：现状系统原理深度分析

## 一、总体架构

### 1.1 架构分层

```
┌─────────────────────────────────────────────────────────────┐
│ 入口层         main.py (CLI)          webui.py (本地Web)      │
├─────────────────────────────────────────────────────────────┤
│ 服务层         breakdown/service.py   run_pipeline()          │
│                流水线编排 · 阶段进度回调 · 取消检查 · 目录准备  │
├─────────────────────────────────────────────────────────────┤
│ 能力层         downloader  transcriber  analyzer  vision      │
│                下载解析     语音转写    七维拆解   画面反推     │
│                rewrite      prompt                            │
│                提示词改写    Prompt 模板资产                    │
├─────────────────────────────────────────────────────────────┤
│ 产出层         render (Markdown)   library (CSV/JSONL)        │
│                mdhtml (MD→HTML)                               │
├─────────────────────────────────────────────────────────────┤
│ 数据层         config.json  reports/  library/  work/  vendor/│
└─────────────────────────────────────────────────────────────┘
```

### 1.2 设计原则（从代码中提炼）

1. **CLI 与 Web 共用一条流水线**：`run_pipeline(url, cfg, opts, on_progress, stop_event)` 是唯一业务入口，CLI 传 `on_progress=print`、Web 传回调把日志行写进任务队列——保证两端行为一致，业务逻辑只有一份；
2. **零框架依赖**：Web 服务用 `http.server.ThreadingHTTPServer`，前端原生 HTML/CSS/JS（无构建、无 npm），Markdown→HTML 自写 100 行转换器——部署=拷贝目录，运行=`python webui.py`；
3. **依赖 vendor 隔离**：`pip install --target vendor` + 包级 `sys.path` 注入（`breakdown/__init__.py`），不污染全局环境，换机/沙箱可复现；
4. **本地优先、数据自持**：模型缓存、临时媒体、报告、库全部落在项目目录，只绑定 127.0.0.1；
5. **容错分层降级**：每一层都有"降级路径"（详见第七节错误处理矩阵）；
6. **禁止编造是硬规则**：prompt 中显式要求"没有的信息填空/null"，报告用"待人工补充"占位——这是区别于"AI 一本正经胡说"的产品红线。

### 1.3 模块依赖图

```
main.py ──► breakdown.config / service / library / utils
webui.py ─► breakdown.* + mdhtml
service ──► downloader ─► yt_dlp (vendor)
          ► transcriber ─► faster_whisper (vendor) | openai (vendor)
          ► analyzer ─► prompt (模板) ─► openai
          ► vision ─► prompt ─► openai (视觉+文本) + PyAV(av)
          ► render ─► utils
          ► library ─► csv/jsonl
config ──► 被除 render/mdhtml 外所有模块引用
```

## 二、模块原理详解

### 2.1 配置系统（breakdown/config.py）

**原理**：三级合并 + 原子写。

1. **合并顺序**：`DEFAULTS`（内置）→ `config.json`（深合并 `_merge`）→ 环境变量（`LLM_API_KEY/LLM_BASE_URL/LLM_MODEL`）→ `vision.active` 预设合入。深合并只递归 dict，标量直接覆盖；
2. **视觉预设机制**：`vision.presets.<name>` 是一套完整视觉模型参数（model/base_url/api_key/max_tokens/frames_per_slice…），`vision.active` 指名生效预设，加载时 `_apply_vision_preset` 把预设字段**合入顶层 vision**——业务代码（vision.py）只读顶层字段，无需感知预设机制，这是"配置多态"的轻量实现；
3. **原子写**：写 config.json 先写 `config.json.tmp` 再 `os.replace`，PermissionError 重试 6 次——应对 Windows 文件共享锁与 Web 并发写；读侧同样重试 3 次防读半截；
4. **占位符防护**：`sk-你的key` 视为未配置（`llm_key_ready`），避免模板配置被误判为已就绪。

**关键边界**：Web 写回（save_cookiefile/save_vision_active）与流水线读可能并发，靠"读重试+写原子替换"保证一致性；Web 并发写同一文件（两个 tab 同时保存）会有最后写入者胜出，当前场景可接受。

### 2.2 下载解析（breakdown/downloader.py）

**原理**：yt-dlp 封装，双轨下载、不合并。

1. **URL 规范化**：抖音精选页/搜索页 URL 提取 `modal_id` 重组为 `/video/<id>` 直链（`_normalize_url`）；平台识别按域名关键词匹配（`_platform`）；
2. **双轨策略**：`fetch_video(..., prefer_combined)`——
   - 纯转写：只下音频轨 `bestaudio/best`；
   - 视觉反推：音频轨 + 视频轨 `bestvideo/best` **分开下载**，各自是单流文件（.m4a/.webm/.mp4），yt-dlp 不做合并 → **省掉 ffmpeg 依赖**（ffmpeg 合并是大多数同类工具需要装系统二进制的原因）；
   - 视频轨失败 → 捕获异常、打印提示、降级返回 `(meta, audio, None)`；
3. **反爬重试**：抖音等平台拦截是概率性的（同一 cookies 时好时坏），外层 for 循环 3 次、间隔 5 秒；最终失败时把 `last_err` 重新抛出并附加 cookies 操作指引（提示文案比裸异常可操作得多）；
4. **产物定位**：按 `%(id)s.%(ext)s` 模板下载到 `work/audio|video/<id>.*`，完成后 glob 过滤 `.json/.jpg/.part` 等副产物，取**体积最大**的文件为媒体本体（应对 yt-dlp 同 id 多格式残留）；
5. **meta 提取**：标题/作者/时长/日期/播放/点赞/评论/简介(500字)/封面缩略图；本地文件走 `meta_for_local_file`（PyAV 时长探测，三级回退：容器时长→视频流时长→帧数/帧率）。

**关键边界**：`cookiesfrombrowser` 新版 Chrome 解密可能失败 → 官方推荐 cookies.txt 文件方案；`noplaylist=True` 防合集误下载；下载文件不清理（work 目录由用户/维护者清理）。

### 2.3 语音转写（breakdown/transcriber.py）

**原理**：双引擎 + 前置预检。

1. **音轨预检**：PyAV 打开容器检查 `streams.audio` 是否存在，无音轨直接抛可读错误——因为 faster-whisper 对无音轨文件的报错是晦涩的 IndexError，预检把错误前置到"人话"层；
2. **本地引擎**：`WhisperModel(model_size, device="cpu", compute_type="int8", download_root=work/models)`——CPU int8 是"无 GPU 也能跑"的取舍；模型下载根目录指到项目内 `work/models/`，避免依赖 `~/.cache` 权限与多机迁移问题；转写参数 `vad_filter=True`（VAD 过滤静音段，提升长视频速度与准确率）、`beam_size=5`；输出归一化为 `[{start, end, text}]`；
3. **API 引擎**：OpenAI 兼容 `audio.transcriptions.create`，`response_format="verbose_json"` + `timestamp_granularities=["segment"]` 拿分段时间戳；Key 支持 `transcribe.openai_api_key` 或环境变量 `ASR_API_KEY`；
4. 转写结果由 `utils.format_transcript` 渲染为 `[MM:SS-MM:SS] 文本` 行——**统一文本中间格式**，后续 analyzer/vision 都消费这个格式，与引擎解耦。

**关键边界**：本地引擎缺失依赖时抛 SystemExit 并给安装指引（或建议 --engine api）；模型下载首次运行阻塞（无进度回调——见已知问题 #7）。

### 2.4 AI 七维拆解（breakdown/analyzer.py + prompt.py）

**原理**：Prompt 资产 + 强约束 JSON + 容错解析。

1. **Prompt 资产（prompt.py，本项目核心）**：
   - `SYSTEM`：七维拆解指令 + 6 条规则（禁编造/前3秒逐秒/骨架时间轴/枚举约束/公式输出/JSON 硬约束）；
   - 枚举清单：`HOOK_TYPES`（8 类钩子）、`SKELETONS`（5 套骨架），用 `%HOOKS%/%SKELETONS%` 占位符注入 SYSTEM——清单与指令同源维护；
   - `SCHEMA_DEMO`：完整 JSON 输出示例（带中文占位值），序列化后内嵌 user 消息——**用"示例即 Schema"替代 JSON Schema 定义**，兼容所有 OpenAI 兼容模型（不是每家都支持 `response_format` 的 json_schema 类型，而 json_object + 示例是最大公约数）；
   - `build_messages(meta, lines)`：视频信息 + 带时间戳逐字稿 + 输出要求三段落拼接。
2. **调用策略**：`temperature=0.3`（稳定性与创造性平衡）、`response_format={"type":"json_object"}`、timeout 600（长逐字稿推理慢）；
3. **容错解析 `_parse_json`**：剥 markdown 代码块 → 直接 `json.loads` → 正则找首个 `{...}` 再解析 → 失败返回 None；
4. **重试链**：调用异常重试 1 次 → 解析失败时在 user 追加"你上一次输出不是合法 JSON，请只输出合法 JSON"再试 1 次 → 仍失败抛错。

**关键边界**：`analyze()` 内部创建 OpenAI client（base_url/api_key 可空串→None），所以 DeepSeek/豆包/智谱/OpenAI 任意兼容服务只需换配置；输出结构与 SCHEMA_DEMO 一致是下游 render/library 的**契约**。

### 2.5 画面提示词反推（breakdown/vision.py）—— 全项目最复杂的算法

**原理**：**分片分帧（slice-and-frame）策略**。核心矛盾：视觉模型单次调用能处理的图像数量有限（实测 8 帧 + 长输出最稳），而短视频通常 40s~3 分钟，全片一锅端必然丢细节或截断输出。

```
时长 D
 │ n_slices = min(max_slices, ceil(D / slice_seconds))     ← 每片 ≤40s，最多 8 片
 ▼
对每片 [s, e)：
  1) 抽帧 extract_frames：片内均匀取 n = min(frames_per_slice, max(4, len/3+1)) 帧
     目标时间点 targets = [s + len*i/(n+1)]（逆序弹出，配合解码流单遍扫描）
  2) 过滤该片逐字稿 _filter_lines（按 [MM:SS- 前缀与区间比较）
  3) 视觉调用 _call_vision：system(反推专家) + user(视频信息+该片逐字稿+帧数说明+片内相对时间指令)
     + ≤8 张 base64 JPEG 图（data URI），temperature 0.3，max_tokens 按预设
  4) 时间偏移 _offset_scene_times：把片内相对时间 +offset 秒 → 全局绝对时间
     ★ 自适应：若分镜最大结束时间 > 片长+5s，判定模型已输出绝对时间，不再偏移（防时间翻倍）
 ▼
合并：
  • 单片 → 覆盖度自检：分镜覆盖 <60% 总时长 → 对后半段补帧再反推 → 文本 LLM 合并
  • 多片 → _merge_slices：把各片 scene_prompts 打包 JSON 交给文本 LLM（如 DeepSeek），
    MERGE_SYSTEM 指令：按时间排序、合并重复/相邻镜头、重编号、汇总整体提示词与风格关键词
  • 合并失败 → _fallback_merge：直接拼接 + 按时间排序（保底不丢数据）
```

**关键技术点**：

1. **抽帧的流式解码**：PyAV `container.decode(stream)` 单遍扫描 + 目标时间点逆序栈——`t >= targets[-1]` 时弹出并取帧，命中即离，O(n) 无需 seek，兼容各种容器；
2. **帧规格**：`img.thumbnail((640,640))` + JPEG quality 80——视觉模型对 640px 足够识别构图/文字，base64 体积约 50~100KB/帧，8 帧 < 1MB 请求体，兼顾速度与成本；
3. **帧数密度**：从"每 15 秒 1 帧"迭代到"每 3 秒 1 帧（上限 8）"——git 历史可见这是实测驱动的调参（分镜粒度修复提交）；
4. **覆盖度自检**（最近一次提交）：模型常见病是"只描述开头几帧"。`_coverage_end` 提取分镜最大结束时间，< 60% 时长则判定漏尾 → 从覆盖点起补帧反推 → 与前半段合并——把"模型偷懒"变成可自动修复的问题；
5. **兜底字段**：合并结果 `setdefault` 补齐 style_keywords/image_to_video_prompt/recreate_notes，避免下游 KeyError；
6. **元信息注入**：`_frame_count/_slice_count` 写入结果，报告/库不展示但可审计调用成本。

**关键边界**：单次调用失败重试 1 次（含 JSON 解析失败追加提示）；单片失败跳过（`continue`）不中断整体；全部失败抛错但被 service 捕获降级为警告（不影响主报告）；`max_slices=8` 是费用阀门——3 分钟视频约 5 片，超长视频按 8 片封顶。

### 2.6 报告渲染（breakdown/render.py + mdhtml.py）

**原理**：字段级容错的模板渲染。

1. **`_g(d, *keys, default="")` 链式取值**：任意层级缺键/None 都返回默认值——LLM 输出再畸形，渲染层永不崩溃，这是"AI 输出不可靠"假设下的防御性编程；
2. **渲染结构**：逐节拼字符串列表（标题/表格/引用），与《爆款视频拆解模板.md》11 节对齐 + 第 12 节视觉反推（有 `visual_prompts` 才渲染）+ 附录完整逐字稿；
3. **文件命名**：`YYYY-MM-DD-<sanitize(title)>.md`，重名加 `-n` 后缀（`while path.exists()`）——同视频多次拆解不覆盖；
4. **mdhtml**：零依赖 Markdown 子集转换器。**先 `html.escape` 再加工**行内元素（链接/粗体/代码）——转义先行保证任何用户/LLM 内容不会注入 HTML（XSS 防线）；块级支持标题/表格/代码块/引用/列表/分隔线/段落合并。

**关键边界**：转换器只覆盖报告用到的语法子集（不追求完整 GFM）；表格解析要求第二行为分隔行（`---`），否则按段落渲染——对 LLM 偶尔输出的畸形表格是优雅降级。

### 2.7 本地库（breakdown/library.py）

**原理**：追加式文件库 + 行指纹。

1. **index.csv**：41 列与人工模板同构（同一套字段体系，Excel 直接可用）；`utf-8-sig` BOM 解决 Excel 中文乱码；空文件时先写表头，之后纯追加；
2. **hooks.jsonl / prompts.jsonl**：每行一个 JSON 对象，追加写。检索 = 逆序读文件（最新在前）+ 关键词对整行 JSON 小写化子串匹配——**量级假设**：数百~数千条时全量扫描毫秒级，不引入索引；
3. **行指纹 `_line_id`**：`md5(行内容)[:12]`——稳定、不依赖行号，供前端"删除"定位；删除 = 读全文件 → 过滤指纹命中行 → 重写（P2 功能，量级小可接受）；
4. **prompt_packs.jsonl**：按 url 覆盖语义（先剔除同 url 旧行再追加）——pack 是"改写结果"，同视频重复改写应更新而非堆积；
5. 解析坏行跳过（`_parse_line` 返回 None），防并发写半截或手动编辑损坏。

**关键边界**：`search_prompts` 会附加 `pack`（查 prompt_packs.jsonl）——检索与改写两个库的关联通过 url 主键；删除只删 JSONL，不动 CSV 与 pack（文档明确声明）。

### 2.8 提示词改写（breakdown/rewrite.py）

**原理**：一次"翻译"调用。把反推的原始提示词（描述性）改写成生成工具（可灵/即梦/Seedance）的**成品格式**——每个工具对提示词结构有偏好（可灵重"主体+动作+环境+镜头语言+光影+风格+画质"结构化长句；即梦重画面感短句；Seedance 走五维架构）。`SYSTEM` 内嵌完整字段契约 + 规则（不添加原画面没有的元素），`response_format=json_object` 强约束，`temperature=0.4`（改写需要一点多样性）。失败兜底用正则提取 `{...}`。

### 2.9 Web 服务（webui.py）

**原理**：线程型 HTTP 服务器 + 内存任务表 + 长任务轮询协议。

1. **进程模型**：`ThreadingHTTPServer` 每请求一线程；任务 worker 也是线程（daemon）——单进程多线程，共享 `JOBS` 字典（全局锁 `JOBS_LOCK` 保护）；
2. **任务状态机**：

```
submit(/api/analyze|/api/upload) → running ──► done (含 report{name,title,md,html})
                                        └──► error (含 error 文案，捕获 BaseException 含 SystemExit)
cancel(/api/cancel) → stop_event.set() → 流水线阶段间检查 → 抛"已取消" → error
```

3. **进度协议**：worker 的 `on_progress(line)` 把日志行 append 到 `JOBS[jid]["progress"]`（锁内）；前端每 1.5s GET `/api/status?id=` 拉全量 progress 数组 + 本地 `seen` 游标增量渲染——**全量传输、增量渲染**，简单可靠；任务保留最近 50 个（内存上限）；
4. **上传**：`/api/upload?name=...` POST 原始字节流，按 `Content-Length` 分块（1MB）写入 `work/uploads/<时间戳>-<name>.part`，完成后 `os.replace` 原子改名——防半截文件；文件名消毒（拒绝 `/ \` 与 `.` 开头）+ 扩展名白名单（视频 14 种 + 音频 8 种）；
5. **配置写回**：`/api/cookiefile`（保存路径到 config.json）、`/api/vision`（校验预设名后写 vision.active，未知预设 400）；
6. **报告回看**：`/api/reports` 列 reports/*.md（倒序），`/api/report?name=` 读文件转 HTML——注意文件名即查询参数，服务端校验存在性（无目录穿越风险因为只拼 `reports/` 前缀 + 存在性检查）；
7. **静态资源**：`/` 返回 index.html，`/app.css`、`/app.js` 直接读文件，`Cache-Control: no-store`（开发期防缓存）；
8. **安全**：仅绑定 127.0.0.1（CLI 参数可改 host）；`log_message` 静默（不刷访问日志）。

### 2.10 CLI（main.py）

**原理**：argparse 子命令 + 便捷默认命令。`raw[0]` 以 http(s) 开头或是文件路径时自动补 `analyze` 前缀——"粘贴即用"体验。`cmd_analyze` 把 CLI 参数映射为 opts 字典传给 `run_pipeline`（与 Web 同构）；`--json` 额外写 LLM 原始 JSON sidecar（.json 文件）；退出码约定：0 成功 / 1 业务失败 / 2 配置缺失；日志统一 stderr、结果 stdout——管道友好。

### 2.11 流水线编排（service.py）

**原理**：五阶段顺序编排 + 取消检查点 + 目录准备。

```
① 下载解析 → ② 转写 → ③ 七维拆解 → ③.5 视觉反推(可选) → ④ 渲染+入库
```

- 每阶段之间检查 `stop_event`（取消）；下载/转写/LLM 调用内部不可中断（无法打断第三方库），取消是"阶段间生效"的协作式取消；
- 视觉反推整体 try/except 包裹——失败仅警告，**不影响报告与入库**（这是"可选增强功能"的边界纪律）；
- 入库存根：`render_report → append_index → append_hook → append_prompt`（有 visual_prompts 才写 prompts 库）；
- 进度文案带 ①②③④ 编号，Web 前端按前缀着色（clsFor）——**进度文案是前后端契约**（l-step 样式依赖 `^[①②③④⑤]` 正则）。

## 三、关键技术选型与理由（现状）

| 环节 | 选型 | 理由 | 备选评估 |
|---|---|---|---|
| 下载 | yt-dlp（vendor 内） | 1800+ 站点提取器、接口更新快、纯 Python | videdown（抖音无水印）可作为补充插件；FFmpeg 二进制被刻意规避 |
| 转写 | faster-whisper | 本地免费、int8 CPU 可跑、CTranslate2 快 | 通义听悟/火山 ASR（api 引擎已留通道）；whisper.cpp 更快但需编译 |
| 媒体解码 | PyAV | 纯 wheel 安装（无需系统 ffmpeg）、抽帧/时长探测/音轨预检三用 | imageio-ffmpeg 需下载二进制 |
| LLM 调用 | openai SDK（OpenAI 兼容） | 事实标准，DeepSeek/豆包/智谱/OpenAI 全覆盖 | requests 手写（省依赖但重复造轮子） |
| Web | http.server 标准库 | 零依赖、单文件、够用 | FastAPI/Flask 需加依赖（V2 如需 WebSocket 再评估） |
| 前端 | 原生 JS + CSS | 无构建链、无 npm、文件即部署 | 无 |
| 存储 | CSV + JSONL 文件 | 量级匹配、Excel 可开、人可读、git 可 diff | SQLite（FR-19 批量导出/统计复杂后升级） |
| 配置 | JSON + 环境变量 | 简单、可手改、示例模板化 | pydantic-settings（过重） |

# 第二部分：后续开发解决方案

## 四、开发环境与工程规范

### 4.1 环境

```bash
# 安装依赖到 vendor（不污染全局）
python -m pip install --target vendor -r requirements.txt   # yt-dlp / openai / faster-whisper

# 验证
python scripts/selftest.py                                    # 冒烟（离线）
python scripts/test_pipeline.py                               # 端到端（mock LLM，离线）
python scripts/test_webui_jobs.py                             # Web 任务机制（离线）

# 日常
python webui.py            # Web（默认 8765）
python main.py <链接>       # CLI
```

Python 版本：3.10+（当前 3.13 验证）；新增依赖一律装 vendor 并更新 requirements.txt。

### 4.2 代码规范

- 模块职责单一，新功能优先进 `breakdown/` 对应模块，业务逻辑**禁止**写在 webui.py 的 Handler 里；
- 所有对外文案中文；进度行保持 `①②③④` 前缀（前端着色契约）；
- 新增"可选能力"（如评论采集）必须带降级路径与阶段错误隔离（参照 vision 的 try/except 纪律）；
- 测试放 `scripts/test_*.py`，一律使用临时目录，禁止触碰真实 reports/library（test_pipeline.py 的教训已固化）。

## 六、实施中的关键技术风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 平台接口变更导致下载失效 | 高 | 下载层保持"可替换插件"形态；失败提示 + 降级本地文件直拆；yt-dlp 定期 vendor 更新 |
| 视觉模型输出质量不稳（漏帧/截断/JSON 坏） | 高 | 已有：分片、覆盖度自检、补帧、容错解析；补充：单片重试次数可配、失败分片记录到日志便于调参 |
| 长视频 LLM 费用失控 | 中 | max_slices/max_frames 已是阀门；批处理加"预计费用"提示（按 tokens 估算） |
| 本地 Whisper 多实例并发 OOM | 中 | 阶段 1.3 并发上限；模型常驻单例（进程内复用 WhisperModel，首次加载后复用） |
| config.json 密钥泄露 | 中 | 已 gitignore；文档强调环境变量优先；阶段 2 评估 Windows Credential Manager 集成 |
| JSONL 长期增长性能 | 低 | 当前量级无忧；超过 1 万条时切换 SQLite（V2.5 评估） |

## 八、部署与运维

- **交付形态**：目录拷贝即部署（含 vendor/ 或部署脚本 `pip install --target vendor -r requirements.txt`）；Windows 可打包 `pyinstaller`（vendor 中已有 yt_dlp 的 pyinstaller hook，说明作者已有此意向）；
